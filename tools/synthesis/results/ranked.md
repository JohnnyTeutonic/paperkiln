### learned-index KV lookup  (splash 3, feasibility 2, id 9f71076e86)

**Claim.** learned-index applied to kv-cache so that a small predictive model replaces explicit per-token key storage for entries the model can regenerate positionally, cutting cost for predictable entries while keeping exact storage for the rest

**New capability.** the system can serve attention queries against a compressed positional model for the bulk of low-salience tokens (e.g. filler, repeated boilerplate) while retaining exact KV for high-salience tokens, something a uniform-cost cache structurally cannot offer

**Placement.** train a tiny auxiliary MLP (per layer) that maps token position + local n-gram context to a predicted key/value; at write time, compare true KV against the model's prediction, and only store an explicit correction residual when prediction error exceeds a threshold, else store nothing but a pointer; the predictor is trained jointly with a frozen nano-gpt2 base on a held-out slice, cache manager is separate from base training.
