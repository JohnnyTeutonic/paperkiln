# Ledger 0002 — the v1 candidate set

*Written 16 Oct 2026, before any of these corpora exists or is trained on.
Rows in `corpus/registry.jsonl` have status `candidate` (or
`retired-at-scale`). The constraint behind every choice: paperkiln models
have about 1–10M parameters and a word-level vocabulary capped at 4,096, in
which a run of digits is one token
(docs/decisions/0001-posttrain-charter.md §1).*

## tinyarith_v1 — the verifiable corpus

1. **Task:** arithmetic word problems in TinyStories register ("lily has 3
   apples and finds 4 more . how many apples does she have ? the answer is
   7").
2. **Target capability:** a correct final number. It has to be checkable
   exactly, because it is the reward signal for PT2–PT5.
3. **Alternatives considered:** GSM8K; MATH; bare arithmetic strings ("3 + 4
   = 7"); a TinyStories-derived counting task mined from existing stories.
4. **Reasons for rejection:**
   - GSM8K: its numbers and vocabulary fall outside a 4,096-word word-level
     vocabulary, and no 10M-parameter model solves it, so the base accuracy
     is zero and RL has no signal.
   - MATH: the same, more so.
   - Bare strings: they contain no format channel ("the answer is"), so the
     reward-hacking probe set cannot be built.
   - Mined counting: an unknown and uncontrolled label distribution.
5. **Contamination:** none by construction. The generator draws train and
   evaluation prompts from disjoint operand pairs, and the card measures the
   disjointness.
6. **Licence:** generated by this repository.
7. **Baseline to beat:** set by the calibration rule (charter §3.2), which
   puts SFT base accuracy in [0.25, 0.60] on the dev split.

## tinystories_instruct_v1 — instruction following

1. **Task:** stories conditioned on stated constraints (required words,
   features, a summary).
2. **Target capability:** following an instruction inside a world and
   vocabulary the model can represent.
3. **Alternatives considered:** Dolly-15k; Alpaca; OpenAssistant; a
   synthetic instruction set written here.
4. **Reasons for rejection:**
   - Dolly and OpenAssistant: open-domain vocabulary, so most content maps
     to `<unk>` under a 4,096-word cap (Dolly ranked last for vocabulary
     fit in `transformer_cpp`).
   - Alpaca: model-generated, and its licence restricts commercial use.
   - Synthetic set: a fallback, if the pinned TinyStories revision does not
     carry the Instruct variant.
5. **Contamination:** shares a source with TinyStories, so overlap with
   `tinystories_slice_v1` is measured, not assumed absent.
6. **Licence:** read from the pinned dataset card.
7. **Baseline:** the C1 pilot's constraint-satisfaction rate on
   `instruct_heldout_v1`.

## simplewiki_v1 — a second register

1. **Task:** expository English.
2. **Target capability:** none as a product. It is the test of whether
   findings made on narrative text are TinyStories artefacts.
3. **Alternatives considered:** WikiText-103; BookCorpus; C4 slices.
4. **Reasons for rejection:**
   - WikiText-103: full-register vocabulary, so `<unk>` dominates at 4,096.
   - BookCorpus: unclear licensing.
   - C4: noisy web text, where quality filtering would become a confound.
5. **Contamination:** measured against the evaluation panel.
6. **Licence:** read from the pinned dump.
7. **Baseline:** bits per byte on its panel member from the C1 pilot.

## Negative controls

`tinystories_slice_wordshuffle_v1` (word order shuffled within each
document) and `tinystories_slice_unigram_v1` (documents sampled from the
slice's unigram distribution) are never "good" corpora. They bound the
corpus effect from below: a corpus that does not beat them on a panel
member has taught nothing that member measures.

A shuffled *vocabulary* is not among them. Permuting token ids is an
isomorphism for a model trained from scratch (charter §8.2).

## code_v1 — retired at this scale

A word-level 4,096-entry vocabulary cannot represent code (identifiers,
operators, indentation), so no code corpus can train a paperkiln model to
emit programs. The `UnitTestVerifier` ships with its tests on fixtures, and
this row records why no code corpus is fetched. It is reopened only if
paperkiln gains a byte-level or subword tokenizer.
