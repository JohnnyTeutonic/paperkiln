# RoPE head coverage in the llama family (fixed 6 Oct 2026)

*The defect record cited by the nine UNDER REVIEW rows of `atlas/findings.jsonl`. The re-run is item 2 of [`../ROADMAP.md`](../ROADMAP.md).*

`ops::apply_rope` rotates every head of q and k when asked (`all_heads`), each head's columns `[h*dk, (h+1)*dk)` with the same adjacent-pair rotation and frequency basis as head 0; with `all_heads=false` it is bit-for-bit the earlier op, which rotated head 0 only (heads 1..H-1 had no position signal). The spec field `arch.rope_heads` selects it: `"all"` for a new run that states nothing, `"first"` for the earlier behaviour. `mtstudio run` records the value in the `model` event and in `out_dir/spec.json`; resuming, `sample`, `chat` and serve's `/sample` use the run's record, and a run that recorded none (every llama run before 6 Oct 2026, e.g. `runs/tinychat-quick`) is `"first"`. A spec stating the other value against a run's record is refused. Tests: `test_rope_heads` (ctest), `tests/test_rope_heads.py`, the H>1 FD checks in `test_gradcheck`.

Affected results: every llama-family run before the fix (llama-tiny; flex routes RoPE to the llama block), hence the nine Atlas Stage 2/3 findings (S2-muon, S2-lr-null, S2-ctx, S2-heads-null, S2-spike-metric, S3-lrxopt, S3-muon, S3-ctx-null, S3-d-unpaid). Each carries an UNDER REVIEW note in `atlas/findings.jsonl` (the registry has no under-review status); S2-heads-null and S3-ctx-null are directly suspect. `tools/reproduce.py` replays registered findings with `rope_heads=first` (as produced) and `--rope-heads all` runs the corrected design; `tools/mtsweep.py` pins `first` when resuming a sweep whose finished runs predate the field. The pre-registered manifests under `experiments/` are unchanged. Open: re-run Stages 2-3 with `rope_heads=all`. The gpt2-family transfer studies (learned positions) are unaffected.

Exports: GGUF llama (`rope.dimension_count = d/H`, interleaved pairs) and `tools/hf_export.py` (per-head permutation to HF's rotate-half) both describe RoPE on every head, so ember.cpp and transformers reproduce `"all"` runs only; the GGUF export event of a `"first"` run with H>1 carries a warning and `hf_export.py` refuses such runs without `--allow-legacy-rope`. The browser engine reads `rope_heads` from its manifest (`tools/export_web_chat.py` writes the run's record, `"first"` when absent); `tools/test_web_chat_parity.py` checks both kinds and that the opposite setting does not match.
