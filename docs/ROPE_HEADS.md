# RoPE head coverage in the llama family (fixed 6 Oct 2026)

*The defect record cited by nine rows of `atlas/findings.jsonl`, and the re-run that checked them.*

`ops::apply_rope` rotates every head of q and k when asked (`all_heads`), each head's columns `[h*dk, (h+1)*dk)` with the same adjacent-pair rotation and frequency basis as head 0; with `all_heads=false` it is bit-for-bit the earlier op, which rotated head 0 only (heads 1..H-1 had no position signal). The spec field `arch.rope_heads` selects it: `"all"` for a new run that states nothing, `"first"` for the earlier behaviour. `mtstudio run` records the value in the `model` event and in `out_dir/spec.json`; resuming, `sample`, `chat` and serve's `/sample` use the run's record, and a run that recorded none (every llama run before 6 Oct 2026, e.g. `runs/tinychat-quick`) is `"first"`. A spec stating the other value against a run's record is refused. Tests: `test_rope_heads` (ctest), `tests/test_rope_heads.py`, the H>1 FD checks in `test_gradcheck`.

Affected results: every llama-family run before the fix (llama-tiny; flex routes RoPE to the llama block), hence the nine Atlas Stage 2/3 findings (S2-muon, S2-lr-null, S2-ctx, S2-heads-null, S2-spike-metric, S3-lrxopt, S3-muon, S3-ctx-null, S3-d-unpaid). `tools/reproduce.py` replays registered findings with `rope_heads=first` (as produced) and `--rope-heads all` runs the corrected design; `tools/mtsweep.py` pins `first` when resuming a sweep whose finished runs predate the field. The pre-registered manifests under `experiments/` are unchanged. The gpt2-family transfer studies (learned positions) are unaffected.

The nine findings were re-run on 10 Oct 2026 with every head rotated (`experiments/atlas_stage2_rope_all/`, `experiments/atlas_stage3_rope_all/`: the same designs, `arch.rope_heads = "all"`, 84 runs on CPU, clean provenance). None is overturned. The six with machine checks replicate under `tools/reproduce.py --check-only`: S2-muon (t -5.67 against a registered -6.21), S2-heads-null (t -0.21), S3-lrxopt (t -3.11 against -3.12), S3-muon (t -6.77 against -7.38), S3-ctx-null (t -1.75) and S3-d-unpaid (t +1.35). For the other three, main effects on the new rows (`receipts/MAIN_EFFECTS_20261010.txt`) match: the lr null holds (t +1.59), the context effect behind the retracted S2-ctx measures t -2.76 against -2.77, and the retracted S2-spike-metric's corrected reading holds (batch on the warmup-excluded spike count t -0.51, on the initial transient t +2.09). Each row's note records its numbers; every status is unchanged.

Exports: GGUF llama (`rope.dimension_count = d/H`, interleaved pairs) and `tools/hf_export.py` (per-head permutation to HF's rotate-half) both describe RoPE on every head, so ember.cpp and transformers reproduce `"all"` runs only; the GGUF export event of a `"first"` run with H>1 carries a warning and `hf_export.py` refuses such runs without `--allow-legacy-rope`. The browser engine reads `rope_heads` from its manifest (`tools/export_web_chat.py` writes the run's record, `"first"` when absent); `tools/test_web_chat_parity.py` checks both kinds and that the opposite setting does not match.
