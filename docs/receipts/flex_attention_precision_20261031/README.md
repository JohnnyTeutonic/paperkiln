# Plain Flex BF16 attention: CPU-only engineering evidence

The opt-in train.attention_precision=bf16 recipe now reaches the existing explicit attention operator through canonical plain Flex blocks. The initial supported path is exact causal attention, learned positions, LayerNorm and tanh-GELU, pre-norm residual blocks with a final norm, and an untied head. Positive integer depth and FFN width use the existing uniform Flex structure. Custom attention/expressions, RoPE/relative attention, SWA, QK normalization, QKV convolution, state tokens, activation checkpointing, global BF16 projections and unsupported objectives are refused. Default FP32 behavior is preserved. Saved scoring/export reconstruct FP32 attention, including when the saved recipe records BF16 training.

CPU model controls cover depth 1 / d_ff 12 and depth 3 / d_ff 20 at d = 8, two heads, vocabulary 7 and two stacked sequences of length 4, each in FP32 and BF16 emulation. All 116 complete gradient tensors pass a NumPy-only full-network forward and explicit reverse reference. The BF16 backward implements the declared six-GEMM quantized-input surrogate; it is not a derivative of bit rounding. The maximum forward normalized error is 1.77e-7 and maximum per-tensor relative gradient error is 1.24e-6, against registered bounds 3e-4 and 0.03. The FP32 reference engine also passes binary64 finite differences at three positions in every depth-one parameter tensor. Fixed parameter values are reconstructed independently from exact name hashes, not trusted from raw inputs.

There are 369 optimized reference/parser controls, including omission, zeroing and NaNs in every gradient tensor, fixture/geometry/type/backend mutations and future six-GEMM profile requirements. The real CPU binary refuses CUDA substitution. Default logits and all gradients are bit-equal to the preserved canonical FP32 composition. The test-only CLI embedding directly checks the production training factory and actual LoadedLM blocks on four real saved recipes: BF16 is selected only for training, and saved inference remains FP32 without changing the inference IR.

The 49 CLI controls include 35 new Flex checks and 14 existing GPT2 regression checks. Actual three-step CPU LM(depth 1 / d_ff 12) and SFT(depth 3 / d_ff 20) lifecycles save model/optimizer checkpoints, reproduce F32 GGUF bytes after loading, and score bit-identically from BF16-recipe and FP32-inference specifications. Independent NumPy and the pinned CPU Ember binary check every 8 × 7 score row and argmax; the largest Ember normalized error is 2.05e-8 against 1e-5. Omitted and explicit FP32 training produce byte-identical model/optimizer checkpoints and F32 GGUFs.

This receipt contains raw arrays, complete checkpoints/exports, source pins, exact library identities, build commands, limits and test logs. CPU libraries are the unchanged source-verified public libraries; only isolated header/CLI/probe objects were built, one core and a fixed 1.5 GiB address-space cap. CPU compilation uses O0 for correctness only. Initial ordinary include-path failures are retained and were fixed without loosening resource limits.

No actual CUDA integration outcome exists for this extension. The harness has strict future CUDA/DEVCHECK/profiler refusal and exact six-BF16-GEMM counts per layer/head, but it has not run on a GPU. The two tiny configurations do not establish exhaustive architecture coverage, full CUDA CLI lifecycle, quality, speed, or broader adoption. No paid resource, watchdog edit, default-branch push, original author worktree change or Ember source modification is part of this work.
