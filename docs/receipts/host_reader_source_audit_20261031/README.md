This is a bounded source-only audit of current public Paperkiln. No production code changed, no compilation or CUDA execution ran, and no exhaustive host-reader or architecture claim is made. The reproducible source inventory is check_source.py.txt; result.json binds exact inspected files and ranges.

Runtime formula primitives inspected: unary_host (exp/log/sqrt/tanh/erf/exact GELU/abs), binary_host (div/pow/min/max), where, rowsum, rowmax and broadcast_cols. Forward materializes each data operand before host loops and creates host-authoritative outputs. Backward materializes upstream gradients. The unary/binary closures additionally read their input/output values, but normal subsequent graph evaluation does not write those data buffers: gradients are separate. A repeated materialize at backward is therefore not justified by absence alone. The documented in-place contract forbids other consumers and output-dependent predecessor closures; violating it is a different semantic error, not evidence of an allowed stale path. No new formula production fix is proposed.

Adjacent checks: rms_row/relu have forward input and backward-gradient materializations and host-built saved values; mul_col/logsumexp fallbacks explicitly materialize their required backward operands. Relative-position/Shaw attention materialize forward operands, retain host-built attention matrices, and materialize backward gradients. This is scoped reasoning, not an independent numerical validation of those operators or all of src/ops.cpp.

A concrete adjacent unsafe boundary exists in public checkpoint in src/autograd.cpp: its NoGrad forward copies inner->data and its backward detached-leaf setup copies xin->data after DEVCHECK guards, without materialization. The public contract requires deterministic recomputation and does not exclude deferred CUDA windows. A deterministic fn(v)=matmul(v,w) is legal, while the CUDA deferred-value condition depends on downloads/window/device ops and not grad_enabled. Such a forward can return a device-fresh output inside NoGrad; the guard then rejects a legal caller, or a non-DEVCHECK build copies stale host bytes. No old numeric failure or device guard rejection was measured here. The second input-copy boundary is independently suspicious when xin is deferred, but must be isolated rather than claiming it executed after the first rejection.

Minimal proposed repair, pending root ownership/review: device::materialize(inner->data) immediately before checkpoint output-copy guard and device::materialize(xin->data) immediately before checkpoint input-copy guard. Keep guards and arithmetic unchanged. No repair is implemented in this receipt.

Meaningful proof plan: preserve exact old source; actual CUDA+DEVCHECK with a nontrivial deterministic matmul checkpoint must record host_stale before the copy, reject old at its precise copy guard, and pass fixed full forward/parent gradients against independent double arithmetic. Add an independent input-only isolate using a test-only old baseline with only the output-copy boundary repaired, or a directly invoked backward closure with a device-fresh input constructed without changing mathematical values. Require an explicit stale assertion at the intended input boundary; a function that materializes its input during forward is not a valid isolate. CPU old/fixed forward and gradient equality, ordinary nondeferred controls, shape/parameter inventory, finite values, and exact deterministic recomputation controls must accompany it. Prospective bounds must be registered before device outcomes. No paid resource or GPU launch is authorized by this audit.
