# Explicit S-full continuation finalizer mapping

`tools/colab_chat/sfull_continuation_finalize_v1.py` creates a new logical view of exactly the nine registered cell/seed combinations and three campaign states. It never changes the historical artifact directories, halted states, frozen finalizers, numerical source or scoring code. Existing view/output/state destinations are refused.

Before invoking the unchanged isolated V2 finalizer once, the adapter checks the prospectively hash-pinned mapping contract; complete original source freeze; exact clean operational commits and named runtime source inventory; every audited baseline hash; unique summaries and identities; all required S-full output paths; fully validated model/AdamW/RNG/event final checkpoints at pretraining step 10000 and SFT step 1500; exact three finished/home job inventories; no owned pod, volume, retired volume or endpoint; and complete inherited seed ledgers under the original $7/$21 estimated-spend caps. Protected original volumes remain in cost accounting only, and must belong to the carried ledger. Full scientific runtime/data/parity/floor predicates remain the unchanged finalizer's responsibility; a nonzero or waiting finalizer verdict is an error, never a pass.

A separate absolute view directory contains `art/c12_CELL_rSEED` and `states/pk_c12_sfull_rSEED_runner` references. Thus seed one's canonical logical name may refer to its separately admitted continuation without overwriting its historical directory or exposing both summaries to selection. The adapter revalidates after the subprocess. It does not enforce filesystem immutability against an unrelated writer; finalizer source/input drift checks remain active.

CLI: `python3 tools/colab_chat/sfull_continuation_finalize_v1.py --contract CONTRACT.json --contract-sha256 SHA256 --view NEW_ABSOLUTE_VIEW --out NEW_ABSOLUTE_OUTPUT --state-dir NEW_ABSOLUTE_STATE [--execute]`. Without `--execute`, it validates only and creates nothing. The contract is an explicit finalization adoption record, separate from launch admission. Its fields are demonstrated in the test fixture: `numerical_commit`, fixed caps, complete `pins`, `original_source_freeze`, `original_manifest`, `frozen_finalizer`, `cpu_budget`, nine `artifact_roots`, and three `campaigns` each with seed, final state, carried ledger, protected original volume IDs, explicit pinned original state and original admission, original admission pins, operational checkout/commit/source pins. Final state and carried ledger paths must themselves be pinned.

## Independent-review hardening

The first adapter revision was withheld from integration after independent review identified two gaps. Output/view/state destinations now must be mutually disjoint and disjoint from every selected artifact directory, old/current state directory, operational checkout and parent directory of each pinned evidence/source file. Equal, ancestor and descendant paths, existing destinations and symlinked ancestor redirection are refused before any view creation or subprocess invocation. Use separate output locations outside evidence/admission directories.

Each campaign now names `original_state` and `original_admission`, both pinned globally and in `original_admission_pins`. The carried ledger must equal that actual original state's complete ledger. The original admission must attest ROOT_ADMITTED, the same integer seed, original numerical source and $7/$21 caps, and its runner state-dir must identify the original state parent. Its reservation must match seed/cap/state/status exactly and belong to its hash-bound aggregate snapshot, whose distinct seed reservations retain the aggregate cap. Synthetic tests use actual admission and reservation JSON shapes, including mutations with hashes deliberately updated so semantic checks, rather than only hash checks, must reject them.
