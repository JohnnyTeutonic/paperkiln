# Experimental train-only GPT2 attention precision, 31 October 2026

`train.attention_precision` accepts `fp32` (default) or experimental `bf16` for exact two-block GPT2 (`gpt2-nano` resolving to the parity model), with the `lm` or `sft` objective. Dimension/head overrides are allowed. Other families, deeper models mapped to Flex, SWA/Kimi/recurrence, state tokens, custom flavor paths, Flash, BF16 projections and activation checkpointing are refused before an output directory is created. The Studio VRAM planner explicitly refuses the uncalibrated dense BF16 attention workspace; explicit FP32 retains its previous estimate.

Precision belongs to each `nn::CausalSelfAttention`, not a process-global attention switch. The unchanged FP32 statement still calls `fused_attention`; opt-in BF16 calls `fused_attention_precision`, whose precision is captured by its tape. Both forward and all four backward attention GEMMs round their operands under the existing explicit-op surrogate. Projections, masters, accumulations and softmax/backward remain FP32. Plain GPT2 already uses per-head fused attention, so no optimized multi-head path was bypassed. The existing global projection/kernel conventions are unchanged; this option introduces no new global mode or reset requirement.

This is a training recipe. The CLI training constructor alone opts into it. LoadedLM used by score, sample, chat and export always constructs FP32 attention, even when the saved spec records BF16 training. Model events and result records use `train_attention_precision`; GPT2 GGUF records `paperkiln.train.attention_precision`. Neither tensor dtype nor the exported inference IR changes. Absent/default settings add no metadata and preserve the old export bytes.

CPU evidence:

- The preserved pre-change library/header harness and candidate produce identical bit dumps of logits, every parameter and full parameter gradients (`preserved_default_dump.txt` and `candidate_default_dump.txt`). A preserved CLI fixed-seed six-step run and candidate have byte-identical safetensors and default GGUF, with identical model, step, evaluation and gradient events. Binary, library, source and output hashes are recorded in `cpu_readiness.json` and adjacent provenance records.
- The C++ integration gate verifies default/explicit-FP32 bit equality, finite nonzero BF16 model gradients, independent instance/tape stability, sixteen tiny AdamW steps, and FP32 save/reload equality. On this fixed synthetic fixture, loss changes from 2.82226539 to 1.35242462. This is execution evidence, not a model-quality result. The existing 44-case explicit-op CPU gate also passes without changed bounds.
- Fourteen actual CLI tests pass, including early rejection and both LM/SFT saves. BF16-trained saved weights score byte-identically under the saved BF16 recipe and an otherwise identical FP32 inference config. Removing the training metadata leaves the F32 GGUF tensor bytes and IR identical.
- An independent NumPy IR forward differs by at most 5.9605e-8 absolute from source inference. Actual CPU Ember prefill and decode differ by at most 2.9803e-8. These compare FP32 inference of the BF16-trained weights; they do not assert that BF16 training equals FP32 training. Raw Ember rows are retained.
- Eight Studio VRAM tests pass, including explicit refusal of the uncalibrated BF16 mode and unchanged explicit-FP32 estimates. The separate default GPT2 head-accounting issue is owned by root and is not changed here.
