# Opt-in DPO startup phase diagnostics

`MICROTORCH_DPO_PHASES=1` enables stderr-only `DPO_STARTUP_PHASE` JSON records for DPO reference-model loading, reference-margin cache begin/end and bounded progress, and the first training iteration begin/end. Other objectives and an unset or zero flag emit no phase records. Progress is emitted for pair1, every32pairs, completion, or after at least5seconds since the previous progress record. Phase timing uses steady-clock wall time without CUDA synchronization, filesystem fsync or secret/user-text fields. Existing stdout and events.jsonl formats are untouched. Diagnostic stdio failures are not promoted to training exceptions.

No model computation, reference order, RNG call, dataset, hyperparameter, checkpoint cadence, source binding or 180-second manager predicate changed. Phase records are not checkpoint progress and do not reset that clock. Enabled telemetry can add overhead and has no measured throughput claim. It will locate the previously silent startup interval on a separately admitted future run; it does not establish where the frozen V3 halt occurred.

Actual compiled CPU CLI validation used a tiny16-dimensional, one-layer, two-head model. A one-step SFT fixture supplies the reference weights. Three matched two-step DPO runs use the flag unset, explicitly0, and1. Final model, optimizer, state and exported safetensors are byte-identical; numerical step events are exactly equal. The actual production full-state publisher records identical RNG reconstruction tuples (seed3, batch2, accumulation1, four draws). This is the existing deterministic-reconstruction record, not a claim to serialize and compare the internal mt19937 engine bytes. The non-DPO SFT fixture with flag1 emits no phase output. Expected on-mode progress1/32/35 and load/cache/first-step ordering pass.

Reproduce: `MTSTUDIO_BIN=BUILT_CPU_CLI OMP_NUM_THREADS=1 python3 -m pytest tests/test_dpo_startup_phases.py -q --basetemp=NEW_EXT4_FOLDER`. Build source hashes and the full source/header match proof for reused cached library objects are retained. The actual CLI and current device.cpp were compiled directly with the normal release flags; device.cpp is supplied separately so the earlier public GEMM repair is included. No unrelated cached source mismatch was accepted. No97M model run, production admission, API/provider call or GPU execution occurred.

Independent read-only review replayed the actual tiny CLI test and approved the source, noting the value of testing an unset flag; the final test now includes both unset and explicit-zero controls. Original DPO setup and checkpoint-gap failures remain unchanged.
